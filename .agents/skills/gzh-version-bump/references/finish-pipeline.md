# 收尾流程（执行器，所有硬门必须过）

阶段 A 产出"改好的新 ebuild"后，依次：

1. **校验（🔴硬门）**：`gzh lint <new_ebuild>`——devmanual 规则 + ~arch。Error 即停。
2. **Manifest（🔴硬门）**：`gzh manifest <new_ebuild>`——fetch distfiles + checksums。fetch 失败即停（检查 SRC_URI）。
   - **截断门**：fetch 成功 ≠ 完整。`gzh manifest` 底层调 `pkgdev manifest --force`，会对被截断的 distfile 照样算哈希写进 Manifest；本地 install 通过（比对的是同一个截断文件），CI 独立重取完整字节时 VERIFY FAILED。对偏大的 distfile（约 ≥50MiB，越大越要查）核对本地文件大小 vs 上游 asset 大小（github 用 `gh api repos/<O>/<N>/releases/tags/<T> --jq '.assets[].size'`，其它源比对 HTTP Content-Length）；不符即 `rm` 该 distfile + 删 Manifest 对应 DIST 行，`curl -L -C - --retry 3` 断点续传后重跑 `gzh manifest`。
   - **取不回来不等于 SRC_URI 写错**：`gzh manifest` 失败先分清三类，别一律去改 SRC_URI。DISTDIR 不可写时 pkgcore 报 `Permission denied` 与 `no write access to distdir`，但同一屏还会打 `failed fetching file: <name>, uri: <URL>`，最像死链的那行其实是权限问题；`portageq envvar DISTDIR` 看目录属主与权限，非 root 且不在 `portage` 组就改跑 `pkgdev manifest --distdir <可写目录> --force <ebuild>`（`gzh manifest` 的命令行里没有 `--distdir`），跑完回到截断门。ebuild 带 `RESTRICT="fetch"` 时 pkgcore 不下载、直接转 `pkg_nofetch`，照它的提示人工把 distfile 放进 DISTDIR 再跑。新版本的下载改成要登录、要点同意条款、或只发有期限的签名 URL 时同样不是 SRC_URI 写错：停下报告交维护者决定，改成 `RESTRICT="fetch"` 加 `pkg_nofetch` 指路，绝不把凭据、token 或临时签名 URL 写进 `SRC_URI`。
   - **同名 distfile 门**：`gzh manifest` 底层是 `pkgdev manifest --force <ebuild>`，路径限定到这一个版本，所以只重算本次版本的 distfile，其余版本的 DIST 行按现有 Manifest 原样搬运。跑完 `git diff -- <pkgdir>/Manifest` 看一眼，正常只新增本次版本的行。旧版本的行被改写，成因是新旧版本落地的 distfile 文件名撞了，多见于 SRC_URI 文件名不带版本号，重算把同名那行覆盖成新字节，旧 ebuild 于是装到新版内容。碰到就停下，给新版加 `-> ${P}.<后缀>` 重命名再重跑 manifest，别让已发布版本静默换掉源码字节。
3. **QA（🔴硬门 Error）**：`gzh pkgcheck <pkg_dir> --min-severity error`——Error 必须清零；Warning 记录不阻断。
   - 注：本步 `gzh pkgcheck` 默认离线（`--net` 默认关、无 `--commits`），不覆盖网络类 SRC_URI 检查（DeadUrl/RedirectedUrl）；overlay 包不在 Gentoo 官方镜像上，死 SRC_URI = 真不可 fetch，由步骤 7 的 `gzh pkgcheck-commits` 覆盖，本步不替代。
4. **编译验证（🔴硬门，只有环境跑不了真 merge 才准降级）**：`gzh build-test <new_ebuild>`（**默认 full**：clean→install）。因为 overlay AGENTS.md 要求每个改动过的 ebuild 都干净装完、只编过不算数，所以唯一可降级的理由是环境跑不了真 merge，例如非 root 沙箱 chown 不到 portage 组；包大或耗时长都不是理由。因为 `--level quick` 的 phase 表只到 `configure`、连 `compile` 都不跑，PHASES 里也没有编到 compile 为止的档位，所以降级时至少手动补跑一次 `ebuild <new_ebuild> compile`，再在交付报告写明 install 被跳过、跳过原因，以及因此没人跑过的检查。失败→提示转 fix-build-failure。注：非 root 环境下 install phase 会因 portage chown 失败，完整 full 需在 root 或 chroot 下跑。
   - **改动过的 ebuild 逐个测**：`emerge-on-pr.yml` 的 scan job 把 PR 里每个有增行的 `*.ebuild` 折成 `=<cat>/<PF>` 各起一条 emerge 腿，只改 `files/`、`metadata.xml` 这类非 ebuild 文件则折成不带版本的 `<cat>/<pkg>`、编当时可见的最高版本，所以 A9 同步过的 `-9999`、A6 改过 `PATCHES` 的旧版本都跟新 ebuild 一样被真 emerge、照判 elog 硬门。本地对每个改动过的 ebuild 各跑一次 `gzh build-test`。live ebuild 编的是上游 HEAD、与本次版本无关，本地跑不动就在交付报告记为跳过并注明 CI 会替你编这条腿；那条腿红了先看日志是不是 HEAD 自身的问题，别回头改发布版 ebuild。
   - **CI elog 硬门复现（build-test 只看 returncode、`gzh pkgcheck` 是静态扫描，两者都不读 Portage elog——而 CI 恰恰在 elog 上判红，这一步补上）**：full build-test 过后照 CI 复现 elog 门。用解析依赖的 emerge，设 `PORTAGE_ELOG_CLASSES="qa warn error" PORTAGE_ELOG_SYSTEM="save" PORTAGE_LOGDIR="$LOGDIR"`（PORTAGE_LOGDIR 默认不设、无 per-ebuild 日志；elog `save` 模块设了时把文件写进 `$PORTAGE_LOGDIR/elog`、未设时写进硬编码的 /var/log/portage/elog，CI 不设此变量、扫默认的 `/var/log/portage/elog/*`），然后扫 **`$LOGDIR/elog` 下的 elog 文件**（非 emerge stdout；`--quiet` 会把 qa-class 如 go.mod 'update BDEPEND' 压掉 console 却仍存 elog）。最忠实于 CI 的复现是照 CI 的顺序：`emerge --onlydeps <目标>` → `rm -rf "$LOGDIR/elog"/*`（清掉依赖产生的 elog）→ `emerge <目标>` → 目录里任一 elog 文件即 CI 会红；这样无需假设 elog 文件名格式。若不清 onlydeps 而想按包过滤，elog 文件名是 `<category>:<PF>:<time>.log`（PF 含 -rN 修订），故 glob 用 `<cat>:<PF>:*`。区分包类型：`-bin`/预编译包 `ebuild <eb> clean install` 够用、扫 stdout 'QA Notice' 但忽略 'Unresolved soname'（RDEPEND 未装的误报，留给 emerge 门）；源码包的 elog 门只有靠解析依赖 emerge 才成立，bare `ebuild install` 不解析 DEPEND。良性（soname 未解析 / CONFIG_CHECK 无内核 / binchecks）注明放行；真问题（rpm_unpack / pre-stripped / desktop-file-validate）改 ebuild。
   - **测试门**：因为 `gzh build-test` 的 phase 表里没有 `test`、CI 的 make.conf 也只往 `FEATURES` 追加 `getbinpkg`，所以带测试的包不本地跑就没人跑过。包有 `IUSE=test` 或上游带测试套件时补跑一次 `FEATURES=test gzh build-test <new_ebuild>`：`run_build_test` 用 `subprocess.run` 继承环境、`ebuild install` 的前置 phase 含 `test`、`FEATURES=test` 同时把 `test` 加进 USE，所以不用改代码，但测试依赖要先 `FEATURES=test emerge --onlydeps <cat/pkg>` 装上。本次改动影响到某个 USE flag 时，该 flag 的每个状态各跑一次。测试挂了怎么收（保最大子集、逐条 skip、`RESTRICT=test`、`PROPERTIES` 的 `test_network` 写法）照 overlay AGENTS.md 的 Commands and QA。跑了哪些组合、哪些没跑写进交付报告。
   - **安装文件集 diff**：因为 glob 安装（`doins -r opt/${PN}/*`、`dodoc LICEN[CS]E.*`）和硬写的 `rm` 清单在上游改目录结构后会静默变成空操作、退出码仍是 0、elog 也不报，所以 full 过后比对新旧版真正装出来的文件集。新版取 `find "$(portageq envvar PORTAGE_TMPDIR)/portage/<cat>/<PF>/image" -mindepth 1 \( -type f -o -type l \) -printf '%P\n' | sort`；旧版已装用 `qlist -e <cat/pkg>`（输出是绝对路径、默认不含目录，比对前去掉开头的 `/`），未装就对旧 ebuild 跑一次 install 取同一口径，旧版本没装也没跑则记为跳过。整批消失或整批多出来的都要能解释：可执行文件、`.so`、`zh_CN` 这类语言目录下的文件、license/notice、`.desktop` 的 basename、多出来的测试二进制。
5. **变更摘要**：`gzh diff-ebuild <old_ebuild> <new_ebuild>`，总结改动与理由。
6. **提交**：`gzh commit <路径...> [-m "category/package: add <PV>"]`。路径按新 ebuild 实际引用的东西算，不是固定的 ebuild 加 Manifest：因为 `gzh commit` 只对传进来的路径 `git add`、又把它们原样当 `git commit` 的 pathspec，所以漏传的文件既不入库也不报错。新 ebuild 引用的每个 `${FILESDIR}` 文件、新增的 `licenses/<Name>`、改过的 `metadata.xml` 都要一起传，否则这个 commit 单独 checkout 装不起来。按 A7 真 drop 时，被删的旧 ebuild 和跟它一起删的 `files/` 文件也算路径：因为手删和 `gzh drop-old --apply` 都只是删文件、不是 `git rm`，删除只落在工作区，`git add <已删路径>` 才把删除登记进 index，而 `git commit` 按传进来的路径当 pathspec，所以漏传就只提交了新增那半、旧 ebuild 原样留在工作区。同一次 drop 还要自己写 `-m "<cat>/<pn>: add <新版>, drop <旧版>"`：因为 pkgdev 生成 subject 时只扫过滤后存在的路径，已删路径永远落在它视野外，自动 subject 只会写 `add <新版>`。A8 改过的 `.github/workflows/overlay.toml` 同样要传，因为没有别的步骤会 stage 它；它和其它非 ebuild 顶层路径混进包 PR 前查 `.github/workflows/emerge-on-pr.yml` 的 `ignore_list`（`.github`、`eclass`、`licenses`、`metadata`、`profiles`、`scripts` 都在表里，不会被当成包原子）。提交后 `git show --stat HEAD` 核对文件清单，drop 时新增与删除两侧都要看到。提交前先看 `git config user.name` 与 `git config user.email`：因为 `--signoff` 的 `Signed-off-by` 直接取这两个值，而 `gzh commit` 只查 `user.signingkey`、不校验身份，所以 `<id>+<user>@users.noreply.github.com` 这类 GitHub 匿名地址会原样写进 DCO trailer；不是贡献者本人的真实姓名和邮箱就停下问人，别自己改 git 配置，也别事后手写 trailer，trailer 一律交给 `pkgdev` 生成。要写 body 时把 subject、空行、body 放进同一个 `-m`：

   ```bash
   gzh commit <路径...> -m "$(printf '%s\n' 'category/package: add <PV>' '' '因为上游把 X 换成 Y，所以 `RDEPEND` 改成 `dev-libs/foo:=`。')"
   ```

   因为 `gzh commit` 的 `-m` 是单值选项、只转发一个 `--message`，整串消息被原样写进提交，所以换行、空行、subject 的 69 字符上限都得自己摆，没人替你截；body 每条改动各占一行。drop 与否见 SKILL 的 A7，subject 与 body 写法见 AGENTS.md 的提交与 PR 文本一节，commit 无 AI 署名。
7. **交付**：默认停在此（本地分支 + commit）。
   - **开 PR 前先 rebase（🔴，URL 门之前）**：`git fetch <canonical-remote> && git rebase <canonical-remote>/master`。因为 `emerge-on-pr.yml` 的 build job 显式检出 `github.event.pull_request.head.sha`、而不是 GitHub 算出的合并结果，所以基底陈旧时 CI 编的是旧 overlay 快照加你的新 ebuild，master 后来落的 eclass、依赖包、profile 改动一概不在，GitHub 也会把 PR 标成 out of date。`gzh pkgcheck-commits` 挡不住这点：它只跑 `git symbolic-ref` 和 `git merge-base`、自己不 fetch，基底旧时 merge-base 照样算得出、门照样绿。有冲突就停下报告，不硬凑。
   - **开 PR 前 URL 硬门（🔴，仅在要开 PR 时跑）**：跑 `gzh pkgcheck-commits`（默认 `--reverify`）——它跑 overlay AGENTS.md 规定的开 PR 前联网门 `pkgcheck scan --git-remote <canonical> --commits="$(git merge-base <canonical>/master HEAD)..HEAD" --net`，范围限本分支、canonical remote 自动解析（`--remote` 可覆盖）。因为 CI 的 pkgcheck 不带 `--net`，所以这不是复现 CI，是补 CI 不做的那一段。它对命中的 SRC_URI DeadUrl/RedirectedUrl 用浏览器 UA 逐条复核、丢弃 GitHub rate-limit 假阳性（HOMEPAGE-only DeadUrl 不阻断安装、已跳过；404/410 判 confirmed 死链，401/403/429 归 needs_human 交人工——工具已内置）。overlay 包不在 Gentoo 官方镜像上，确认为死的 SRC_URI = 真不可 fetch，须处理后再开 PR。扫描结果里仍混着别的包时，用 `gzh pkgcheck "$(gzh repo)/<cat>/<pkg>" --net` 单包复核本次改动，不加 `--min-severity`：因为 DeadUrl/RedirectedUrl 是 warning 级、`--min-severity error` 会让退出码在确认死链时照样为 0，所以保持默认的 warning 门。单包扫描不做 commit-only 那几项检查，它只是自己这份改动的实锤，不替代上面的 commit 扫描。
   - **抬高的工具链下限还没进树就开 draft（🔴，人工确认门之前）**：本次抬了 `>=dev-lang/go-*` 的 BDEPEND 或 `RUST_MIN_VER` 时，先确认树里真有那个版本。Go 查可见 ebuild：`portageq best_visible / ebuild '>=dev-lang/go-<X.Y.Z>'`，有匹配打印版本、rc=0，无匹配空输出、rc=1。别用 `portageq match`，因为它查的是本机已安装的包不是 ebuild 仓库，所以树里有而本机没装时它同样空输出且 rc=0，会把正常 PR 误判成要 draft。`RUST_MIN_VER` 不是 atom，`rust.eclass` 拿它对齐到某个 slot 后生成 `|| ( >=dev-lang/rust-bin-… >=dev-lang/rust-… )`，所以对 `dev-lang/rust` 和 `dev-lang/rust-bin` 各查一次，两个都无匹配才算未进树。rc=1 也可能是树里有但被 mask 或没 keyword，用 `ls "$(portageq get_repo_path / gentoo)"/dev-lang/go/` 区分，仓库路径动态取、不写死。未进树就 `gh pr create --draft`，正文引上游 `go.mod` 的 `go` 行或 `Cargo.toml` 的 `rust-version`，并附 packages.gentoo.org 上的当前树版本（本地树可能没同步，以它为准）。因为门槛版本进树之前依赖解析不开，所以先挂 draft 等它进树，不当普通 PR 送审。
   - **人工确认门（🔴，URL 门过后）**：把确切的 PR 标题、正文、文件清单给人看，取得**这一个 PR** 的确认再开；批量放行不算，draft 也一样。正文写法见 AGENTS.md 的提交与 PR 文本一节：与 commit body 同一套理由、单一语言、不报通过的测试，例行 bump 只需 `Closes #N`，PR 模板的勾选框只勾真的跑过的。
   - **确认后先 push 再开 PR**：因为 `gh pr create` 不会替你把分支推上去，所以先 `git push <personal-fork> <branch>`（rebase 过用 `--force-with-lease`），再开 PR。因为 `gh pr create` 只在交互提示时才套仓库模板、非交互下不给 `--title`/`--body` 会直接报错、`--template` 又不能和 `--body-file` 同用，所以自己把描述叠到模板上方：

     ```bash
     body=$(mktemp)
     { printf '%s\n\n' "<描述>"; cat "$(gzh repo)/.github/pull_request_template.md"; } > "$body"
     gh pr create --repo gentoo-zh/overlay --base master \
       --head "$(gh api user --jq .login):<branch>" \
       --title "$(git log -1 --format=%s)" --body-file "$body"
     ```

     标题取 `git log -1 --format=%s`，因为 `gzh commit` 底层是 `pkgdev commit`，那就是 pkgdev 落下的英文 subject 原文，不另写不翻译。模板里 `pkgcheck scan --commits --net` 那个勾选框由本步的 `gzh pkgcheck-commits` 满足、真跑过才勾；另一个是人对 AI 产出的背书，agent 不代勾。personal fork = remote URL 的 owner 等于 `gh api user --jq .login` 的那个，动态解析；解析不出唯一一个就停下报告，这只挡发布、不挡本地改动。只 push topic 分支，绝不 push master 或 canonical remote。
   - **盯 CI（PR 开出去之后）**：`gh pr checks <n> --repo gentoo-zh/overlay --watch --interval 60`。红了先拿失败 job 的日志原文再判类型，别看 job 名猜：因为整个 run 还在跑时 `gh run view <id> --log-failed` 会拒绝输出，所以改用 `gh api repos/gentoo-zh/overlay/actions/jobs/<jobid>/logs`。elog 红按步骤 4 的良性与真问题分法、以及 [prebuilt-qa.md](prebuilt-qa.md) 第 6 节判。重试上限仍是 3 次。

**重试上限 3 次**：任一硬门/编译同一错误重复 2 次即停，报告失败步骤+错误+每次尝试，询问继续/跳过/放弃。
